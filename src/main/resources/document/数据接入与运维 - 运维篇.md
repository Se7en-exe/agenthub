# 数据接入与运维 - 运维篇

本文面向接入方与运维同学，说明接口限流、错误码、重试与 SLA。

---

#### 接口限流是怎么做的？

按「账号 + 接口」维度做令牌桶限流。对话类接口标准版 2 QPS、专业版 20 QPS、企业版按合同；知识库写入类接口统一 5 QPS。触发限流返回 HTTP 429，响应头带 X-RateLimit-Limit、X-RateLimit-Remaining、X-RateLimit-Reset（Unix 秒）。客户端应读取 Reset 后按指数退避重试，不要固定间隔轮询。

---

#### 常见错误码怎么排查？

401 InvalidApiKey：密钥错误或已被轮换，检查是否用了旧密钥、是否多带了空格。
403 QuotaExhausted：额度用尽且开启了硬停，充值或关闭硬停。
429 RateLimited：见上一条限流说明。
500 InternalError：服务端异常，带请求 ID 提工单，通常 5 分钟内自愈。
504 UpstreamTimeout：上游模型超时，流式接口表现为中途断流，客户端应保留已接收内容并允许重发。

排查顺序建议：先看响应头里的 X-Request-Id，再在控制台「调用日志」按该 ID 检索，能看到完整链路与失败节点，比反复试错快。

---

#### 流式接口中途断开怎么处理？

SSE 连接默认空闲 60 秒断开，长回答需要服务端持续心跳。客户端收到断流时不要直接丢弃，已接收的片段是有效内容，可拼接展示并提示「回答可能不完整」。重试时带上 conversationId 与已生成内容的末句，让模型续写而不是重答。

---

#### 服务可用性承诺是什么？

标准版不承诺 SLA。专业版月度可用性 99.5%，企业版 99.9%，按自然月统计，低于承诺按合同比例返还服务费。计划内维护提前 72 小时公告，不计入不可用时长；不可用时长以平台监控为准，双方数据不一致时以第三方拨测为仲裁依据。
